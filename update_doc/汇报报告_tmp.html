Multi-hop Trace Gate 汇报报告

1. Motivation

多跳问答的核心难点不是单次检索，而是每一步检索都会影响后续推理链。如果某一 hop 取错 evidence，后面的子问题会基于错误上下文继续展开，错误会沿着 reasoning chain 放大。现有方法常见问题包括：

  • 静态检索缺少过程反馈：只按当前 query 的 embedding 相似度取 top-k，无法判断“当前推理状态是否已经偏离”。
  • query decomposition 只解决问题拆分，不解决错误传播：分解模型能把复杂问题拆成多个子问题，但后续每一步是否应该重新检索、扩大候选或重排，仍然缺少机制。
  • LLM 自我判断成本高且不稳定：让 LLM 每一步反思是否错了，推理成本较高，且容易受 prompt 与上下文扰动影响。
  • 长 hop 数据更少：3-hop / 4-hop 样本天然少，直接训练 gate 会让后几步 transition 学得不稳定。

本项目尝试用一个更轻量的方式解决这个问题：先构造可控的 correct / error reasoning trace，再从 Llama hidden state 的 transition 中学习一个 gate。gate 的目标是判断当前 hop 前后的隐藏状态变化是否异常，从而在端到端召回时触发检索干预。

3. Method

整体流程可以理解为五步：

原始多跳数据
  -> BART question decomposer
  -> MuSiQue correct / counterfactual reasoning traces
  -> Llama hidden-state transition features
  -> PCA + Logistic Regression gate
  -> BART 分解驱动的端到端多跳召回

3.1 BART Decomposer

代码位置：decompose/bart/

项目首先训练一个 BART-large decomposer，将原始复杂问题拆成多个自然语言 sub-question。训练数据包括：

  • MuSiQue 官方 BART 格式训练集；
  • 经过 GPT 标注的 2Wiki mixed train/dev；
  • 输出格式先是官方 [[CQS]] / [[CQE]] hop 格式，再转换成自然语言 sub-question。

当前 checkpoint：

  • outputs/bart_decomposer_musique_2wiki_repro/checkpoint-1425
  • 训练 3 epoch，learning rate = 1e-5，batch size = 16，bf16。

Decomposer 的作用不是直接回答问题，而是给下游 retrieval pipeline 提供每一步要问什么。

3.2 Trace 构造与 Query Rewrite

代码位置：traces/

训练 gate 不能只依赖模型自然犯错，因为自然错误不可控、标签不稳定。因此项目构造了两类 trace：

类型 evidence 设置 label 含义
correct trace 每个 hop 都使用 gold evidence 所有 transition 都不需要干预
counterfactual trace 指定 hop 注入 cosine top-k 中的非 gold passage 对应 transition 标为需要干预

负例构造方式：

  1. 对每个 hop 的 sub-question 做检索 query。
  2. 把 [Answer N] 用前面 gold hop answer 展开，保持线上使用方式一致。
  3. 从 BGE cosine top-k 中选择非 gold passage，替换该 hop 的 gold evidence。
  4. 只把第一次错误 hop 对应的 transition 标成正类，即 should_intervene(j) = (j + 1) in wrong_hops。

为缓解长 hop 数据少的问题，train split 对 3-hop / 4-hop 的 MuSiQue 分解做了 query rewrite 增强：

  • 输入：data/decompose/musique/gt/train_nl.jsonl
  • 输出：data/decompose/musique/gt/train_nl_enhance.jsonl
  • 目标 hop：3、4
  • 生成 5,562 个候选，最终写入 5,562 条，其中并入 trace 构造的增强样本为 4,132 条。

3.3 Hidden State Extraction

代码位置：hidden_states/extract_hidden_states.py

对每条 reasoning trace，项目使用 meta-llama/Llama-3.1-8B-Instruct 提取每个 cumulative prefix 的最后 token hidden state：

h0: Question
h1: Question + Evidence 1
h2: Question + Evidence 1 + Evidence 2
...

gate 使用的是 transition delta：

Delta_j = h_j - h_{j-1}

实现上每个 prefix 独立 full forward，不使用 incremental KV；默认读取第 31 层 hidden state，dtype 为 bf16。

3.4 Gate Training

代码位置：gate/

gate 是一个轻量分类器：

4096-d hidden delta
  -> PCA 到 64 维
  -> Logistic Regression
  -> abnormal score
  -> threshold 判断是否触发干预

当前使用 pooled-by-transition 协议，即按语义 transition 合并不同 K 的样本：

j transition 使用的 K
0 Q -> E1 2, 3, 4
1 E1 -> E2 2, 3, 4
2 E2 -> E3 3, 4
3 E3 -> E4 4

不训练 final transition，因为 final answer 阶段没有对应的 evidence selection hop。

3.5 End-to-end Retrieval

代码位置：retrieval/run_retrieval_exp_wavefront.py

端到端流程如下：

  1. BART decomposer 生成 dev 集 sub-questions。
  2. 每个 hop 用 BGE-base-en-v1.5 做 cosine retrieval，取 top-k。
  3. Llama 根据当前上下文从候选中选择 passage 并生成当前 hop answer。
  4. gate 对 hidden-state transition 打 abnormal score。
  5. 如果 gate 认为 top candidate 异常，则扩大候选并使用 cosine + lambda * LR score 做 rerank。
  6. 所有 hop 完成后，用 final reader 根据 reasoning trace 输出最终答案。

当前结果使用 gated_rule_a，lambda_lr=0.25，topk=10，expand_topk=10。

dev 上 pooled LR gate 的整体结果：

AUC TPR FPR Precision F1
0.9074 82.35% 17.56% 70.84% 76.16%

按 transition 看：

transition TPR FPR Precision F1
Q -> E1 86.59% 16.58% 66.34% 75.13%
E1 -> E2 81.59% 18.41% 72.88% 76.99%
E2 -> E3 78.03% 20.06% 74.26% 76.10%
E3 -> E4 74.07% 14.81% 83.33% 78.43%

按 K 看，链越长检测越难：

K TPR FPR Precision F1
2 86.38% 18.48% 75.71% 80.69%
3 81.32% 18.25% 69.02% 74.67%
4 77.59% 15.93% 66.09% 71.38%

结论：hidden-state delta 中确实包含可学习的错误信号。gate 不是完美分类器，但能以较低成本捕捉大多数被注入错误的 transition。

4.5 End-to-end Retrieval Results

当前完整端到端结果来自 session：

retrieval/results/20260628_120339_wavefront_pooled_lam0p25/

数据集 n examples k match hop recall@1 hop recall@3 MRR chain recall@1 chain recall@3 selection acc
MuSiQue 2,417 83.82% 65.13% 80.44% 72.02% 42.33% 64.71% 61.77%
2Wiki 12,576 98.66% 84.84% 94.01% 88.99% 66.84% 85.89% 79.73%
HotpotQA 7,405 87.63% 61.86% 81.68% 70.78% 40.93% 61.26% 57.19%

其中：

  • hop recall 表示每个 hop 的 gold evidence 是否被召回。
  • chain recall 表示整条链的所有 gold evidence 是否都被召回。
  • selection acc 表示 Llama 从候选 passage 中选中 gold evidence 的比例。
  • k match 表示 BART 预测 hop 数与 gold hop 数一致的样本比例。

结果解读：

  • 2Wiki 表现最好，主要因为 BART 在该数据上的 hop 数匹配率高，且 evidence selection 更稳定。
  • MuSiQue 与 HotpotQA 的 hop-level recall@3 都在 80% 左右，但 chain-level 指标明显下降，说明多跳链式任务中单步错误会迅速累积。
  • MuSiQue 4-hop 的 decomposer hop count acc 只有 48.89%，这会限制端到端上限；因此后续提升不仅要改 gate，也要继续改长链分解。

相对 baseline，gated_rule_a 在三个数据集上都提高了 hop-level 和 chain-level 召回：MuSiQue 的 chain R@3 从 59.37% 提升到 65.16%，2Wiki 从 82.79% 提升到 90.16%，HotpotQA 从 55.08% 提升到 61.07%。这说明 gate 不只是离线分类有效，在端到端召回链路中也能带来稳定收益。

5. Current Findings

当前版本已经证明了三点：

  1. 可控反事实 trace 是有效训练信号
    通过替换某一 hop 的 evidence，可以精确知道哪一个 transition 应该触发干预，避免依赖 LLM 自然错误。

  2. hidden-state transition 能反映推理链异常
    pooled LR gate 在 dev 上 AUC 达到 0.9074，说明 Delta_j = h_j - h_{j-1} 包含可分离的错误信息。

  3. 端到端效果受 decomposer 和 selection 共同限制
    gate 能提供异常检测信号，但最终 chain recall 还取决于 hop 数是否预测正确、候选池是否包含 gold evidence、以及 Llama 是否选中正确 passage。

6. Limitations and Next Steps

旧版实验中已经保留了 baseline 对比，结果显示 gated_rule_a 相比 baseline 在 MuSiQue、2Wiki、HotpotQA 上都有稳定召回提升。当前仍需要注意的是：不同结果来自不同实验目录，严格写论文表格时应统一 session、统一脚本版本、统一评测字段。

后续建议：

  • 将当前 in-pool 召回扩展到全局检索，不再只在每个样本约 20 条候选段落内检索；全局候选可先用 ColBERT 做粗筛，再进入 gate / rerank 阶段。
  • 当前 cosine + lambda * LR score 的组合权重是固定超参，后续可以训练一个简单的融合 gate / ranker，学习如何动态组合相似度分数与异常分数。
  • 对 4-hop decomposer 做专项增强，减少预测 hop 数偏短的问题。
  • 分析 gate 的 false positive：正确 trace 上触发过多会带来不必要 rerank。
  • 继续完善 answer-level EM / F1；旧实验已有 EM 字段，但部分跨数据集结果缺少 F1。
